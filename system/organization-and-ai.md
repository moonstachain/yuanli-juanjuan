# 叙世空间｜组织与AI系统

版本：v1.1 · 2026-09-22 · 公开整理版

## 组织目标

让客户理解、设计判断、执行经验与复盘反馈能够被团队接续使用。系统价值需要由实际使用、交付与工时变化证明。

## 六个工作模块

| 模块 | 最小输入 | 最小输出 | 验证重点 |
| --- | --- | --- | --- |
| 获客 | 线索与选择原因 | 客户适配与下一步 | 线索质量及口径清楚 |
| 客户理解 | 访谈、问卷、确认 | 需求与故事说明 | 团队是否理解一致 |
| 设计判断 | 概念、场地、约束 | 判断理由和修改方向 | 返工是否更有方向 |
| 报价 | 范围、材料、工时与变更 | 可解释的报价版本 | 是否反映实际投入 |
| 项目管理 | 承诺、排期、责任 | 确认、提醒与异常记录 | 是否稳定触发动作 |
| 复盘 | 交付、成本、反馈 | 可复用方法和改进 | 是否进入下一项目 |

经营主链为：线索 → 沟通 → 报价签约 → 设计 → 执行 → 收款结算 → 复盘。每个环节尽量沿用同一项目编号，连接信息、责任与版本。

## 品味函数卡：从打分到指导修改

以下为根据研究整理的试用框架，不代表已有正式评分制度。

| 判断维度 | 必须回答的问题 | 未达到时的动作 |
| --- | --- | --- |
| 客户核心需要 | 新人／品牌最在意什么 | 回到访谈与确认 |
| 专属性 | 哪些细节来自这位客户 | 补充关系与经历依据 |
| 逻辑与情感 | 故事、行为与感受是否连贯 | 简化或重建主线 |
| 空间与参与 | 构成、动线、理解及互动是否成立 | 模拟路径，调整场景 |
| 可靠交付 | 预算、时间、材料、技术是否匹配 | 打样、减法或备选方案 |

共同的情感入口可以与专属细节共存。不能因为其他人也能共鸣，就认定方案没有定制价值。

每次判断保留依据、建议修改、客户反馈与最后结果，用真实反馈修正标准。AI可辅助整理信息、查找历史案例、对照规则和汇总复盘，最终设计与承诺由负责人确认。

## 用一个小闭环检验系统

选取一个项目中的明确问题，例如需求交接、方案评审或负荷判断。记录使用前的事实基线，再观察新方法的执行与结果。

可记录返工轮次及原因、确认遗漏、创始人介入次数及时间、项目工时、节点兑现和客户反馈。先统一统计口径，再设目标；当前不填造基线或改善比例。

## 复制之前

总部与城市伙伴需要真实支持能力：获客、标准、训练、品控、统筹和经济可持续性。文档数量、界面原型或系统模块存在，都不能单独证明组织已经具备复制条件。
